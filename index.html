🖥️ Content Editor (In-Game Settings Hub)

⚙️ What is the Content Editor?

Overview

Added in version 6.0.0, the Content Editor is an in-game settings hub for your campaign. It replaces most manual JSON file editing with a proper web UI (WebView2 + localhost, same underlying tech as the redesigned Memory Book) that opens directly over the game.

How to open: Pause menu (ESC on the campaign map) → AI Influence Settings. It's always available there when the mod and campaign are active, regardless of other panel-blocking rules (battle simulation, army management, save, etc).

Tabs
  • World — world description, public facts and secrets NPCs may know, cultural traditions per faction. AI can help draft descriptions, facts, and secrets. You can redistribute who already knows what across met NPCs, and batch-generate AI personalities for rulers who don't have one yet.
  • Character — how NPCs see your hero. Also where you create custom companions and family members (son, daughter, spouse, parent, sibling): they join your party immediately, then you customize appearance while the AI fills in personality. On the Character page you can also build a full family tree (parents, siblings, spouse, children, other relatives) with shared family history, then create everyone in your clan at once — links are stored via the game's native Hero relationships.
  • NPC — searchable list with portraits and favorites. Per character: description, voice, AI personality, known facts/secrets, dialogue history, romance progress. You can generate or refresh an NPC's AI personality without talking to them in-game first, and edit dialogue lines directly (deletions/changes apply to the live in-game context immediately, not just the JSON on disk).
  • Events — create and edit world events by hand: headlines, importance, who knows about them, economic effects on towns/villages, epidemics, diplomatic pressure, and links to ongoing effects/diseases in the campaign.
  • Prompts (Full mode only) — advanced editing of the mod's text templates, with placeholders and reset-to-defaults.
  • Service — open the save folder directly, restore or delete automatic file backups.
  • Import / Export — copy world data, facts, secrets, traditions, or prompt packs between campaigns or from a file.
Simple vs Full mode

Simple mode covers the essentials; Full mode adds direct prompt template editing. Interface is available in Russian and English, with built-in tips on every page, undo support, and a save confirmation before leaving unsaved work.

Companion selection with family members

Family members in your party (parents, siblings, spouse, children, other clan relatives created via Content Editor) can now appear in the "who to bring with you" window when entering a location, the same as regular companions. People the game has already placed in the settlement on its own are excluded — you only choose who is still outside and should enter with you.

Display mode limitation
⚠️ Not available in exclusive Fullscreen mode. The Content Editor and Memory Book are both blocked in exclusive Fullscreen display mode (with an in-game message explaining why). Use Windowed or Borderless Fullscreen instead — the shared web view can only embed as a child window in those modes.

🧠 Memory System & Conversation RAG

📖 How NPC Memory Works Now

Conversation RAG (since 6.0.0)

Long dialogue history no longer needs MEMORY-line compression inside the prompt. The mod keeps the full conversation log in the save and sends the AI a smart slice instead:

  • Always included: the last N messages, where N = Maximum Conversation History Length in Prompt Settings.
  • When history is longer than N: up to Top‑K relevant past chunks (dialogue + long-term memory) are retrieved from the full log.
  • Search method: BM25 locally by default; with the Player2 backend, semantic embeddings are also available (via POST /v1/embeddings), with Hybrid and Auto retrieval modes. Embeddings are indexed in the background and stored per NPC in the save folder.
  • Legacy compatibility: old MEMORY (day …) lines from pre-6.0.0 saves, plus new Memory System entries, are indexed as separate chunks and surfaced only when relevant — not dumped into every prompt.
  • Works across live dialogue, NPC messenger letters, and letter replies (same underlying prompt generator).

MCM group: Conversation RAG — enable/disable, retrieval mode, Top‑K, chunk size, embedding dimensions (0 = launcher default).

Memory System — visual memories only (since 6.0.0)

Memory consolidation no longer deletes or rewrites lines in ConversationHistory. New memories go straight to the Memory Book / notifications (and optional Player2-generated images); token savings for old dialogue are now handled entirely by Conversation RAG instead of inline MEMORY lines.

Every N dialogue messages (default 25, configurable in MCM → Memory System), the selected AI backend condenses an NPC's accumulated history into a memory entry. Distorted overheard lines are never counted. Processing happens gradually in the background while you travel the campaign map.

Memory Book — redesigned UI (since 6.0.0)

Fully redesigned web UI (WebView2 + localhost) that replaces the old Gauntlet-based screen with an open-book layout:

  • Left page: scrollable list of memories (title + campaign day)
  • Right page: scene illustration in a gold frame, title, summary, and NPC metadata
  • Dark leather cover, parchment pages, gold accents, serif typography — matches the Content Editor's visual style
  • Navigate via list clicks, Previous/Next, arrow keys, or Escape to close

Opening it: quest screen button, a configurable hotkey (F1–F12, MCM → Mod Settings), or clicking a map notification (jumps straight to that memory). Interface strings follow the game's language.

MCM: Memory Book port (default 17852).

The quest-screen button and map notifications are hidden whenever the memory system or the mod itself is disabled, not just when "Keep Memory Book" is off — settings changes apply immediately, and an already-open book closes if memory features get disabled mid-session.

Illustrations

Image generation (Player2 backend only, disabled by default) creates a photorealistic scene per memory, using in-game portraits and appearances of up to 4 mentioned characters. Scene description and character references are saved with every memory entry even when image generation is off, so you can generate the illustration later — the book shows a "Generate illustration" button whenever scene data exists, and clicking an existing image lets you regenerate it.

Known issues
Memory Book not opening for some players: some players can open the book via the quest screen or map notification, others can't — this is still being investigated. The configurable hotkey (F1–F12) was added specifically as a workaround, along with better failure tracking to help diagnose the issue in future updates.

❓ Frequently Asked Questions

📌 Where should I ask questions about the mod?

Answer: Check FAQ first, then use Discord for mod discussions.

⚠️ What should I know about the BETA status?

Answer: AIInfluence is in BETA. Bugs, weird NPC behavior, and unexpected AI actions are normal. Report issues in appropriate channels.

🎮 Which Bannerlord versions are supported?

Answer: AI Influence currently officially supports Bannerlord 1.4.x only.

1.4.x support was added in version 5.0.1 (alongside 1.3.15 at the time), but 1.3.15 is no longer supported by current mod releases. If you're still on 1.3.15, update your game to 1.4.x before installing the latest mod version.

🖥️ Can I use a local LLM / offline AI model (Ollama, KoboldCpp, LM Studio)?

Answer: Technically the mod supports local AI endpoints, but we strongly discourage it. Local models are generally far too weak for AI Influence's complex prompt system, which includes diplomacy chains, NPC memory, dynamic events, and action parsing. You will likely experience:

  • NPCs giving short, repetitive, or broken responses
  • Actions and commands being ignored or misinterpreted
  • Diplomacy system failing to function correctly
  • Overall poor roleplay quality

Use a cloud-based API (OpenRouter, DeepSeek, Player2 with a capable model) for the intended experience.

💸 Are there any good free AI models I can use with AI Influence?

Answer: Unfortunately, there are no permanently free AI models that perform well enough for AI Influence. Free-tier options occasionally appear temporarily (limited free credits, promotional periods, etc.), but they are either rate-limited, low quality, or discontinued after a short time — none of them offer a consistently good experience.

For a proper AI Influence playthrough you need a paid solution. The most cost-effective options are:

  • Player2 — daily free energy spinner + paid plans, easy setup
  • DeepSeek API — very affordable, good quality
  • OpenRouter — pay-per-token, access to many top models
⚙️ What is the minimum AI model I should use with Player2?

Answer: When using Player2, you must select at least DeepSeek V3 (3.2) or an equivalent-tier model. Anything cheaper or weaker than DeepSeek V3/3.2 will not run AI Influence at full functionality — expect degraded NPC dialogue, broken action chains, and poor diplomacy responses.

In Player2's model selector, always pick a mid-tier or higher model. The smarter the model, the better the in-game experience.

⚙️ How do I set up MCM AI Backend?

Answer: MCM → AI Backend → Select provider (Player2, OpenRouter, etc.) → Enter URL and API key if required → Press "Test Connection" to validate.

❤️ What are Romance settings?

Answer: MCM → Romance (BETA) settings:

  • Minimum romance level for marriage (default 50)
  • Romance with married NPCs (OFF by default)
📰 How do Dynamic Events work?

Answer: AI analyzes dialogues and creates news, rumors, and political events. These spread between NPCs and can influence alliances, trigger wars, or peace agreements. ⚠️ Some features are experimental.

👑 How do I declare war, make peace, or form alliances as a ruler?

Answer: If you are a king/queen, you can issue diplomatic commands through your governor (the NPC assigned to your fief). When talking to your governor, simply state your political decision in character (e.g., "I want to declare war on the Western Empire" or "Propose peace with Battania"). The governor will then publish an official statement on your behalf, which appears in blue on the campaign map. The AI rulers will evaluate your declaration and react accordingly. You must have a governor appointed in one of your settlements for this feature to work.

🔄 How do I transfer troops or prisoners between my party and an NPC party?

Answer: The NPC can use the transfer_troops_and_prisoners action. When talking to a mobile NPC party (not in your own party), you can ask them to give or receive specific troops/prisoners. The NPC must have those units available. Mention exact troop names from the "Your Forces" / "Your Captives" lists, and the AI will decide whether to agree based on personality and situation.

📜 What is create_rp_item and how do I use it?

Answer: create_rp_item lets an NPC physically give you a roleplay item (letter, document, token, etc.). The item is automatically added to your inventory. Before creating it, the AI checks your inventory to avoid duplicates. You can ask an NPC to write a letter, sign a document, or offer a keepsake — if they agree, the action creates it on the spot.

🔍 How do I find my campaign ID for editing save files?

Answer: Open the mod log at Modules/AIInfluence/logs/mod_log.txt and look for a line like: Created save directory: ...\save_data\b7ed0c2f2399. The last part (b7ed0c2f2399) is your campaign ID. You can also use MCM → Debug → Show Save Folder Info.

👥 Multiple NPC Conversations

🔄 Dual-Conversation Format Tutorial

1. What This Tutorial Covers:

This tutorial explains how to enable conversations with multiple NPCs simultaneously, a feature not natively supported by the mod but possible through custom configurations.

2. Compatibility:

Works with every version of Bannerlord/Warsails. It explores AI possibilities and prompt engineering techniques.

3. Initial Setup:

Go to MCM settings in-game:

  1. Set maximum AI response to 1000 characters
  2. Set minimum AI response to 300 characters
4. Edit world.txt File:

Add the following rule to your world.txt file:

DUAL-CONVERSATION FORMAT (universal roleplay rule) Whenever the player explicitly asks an NPC to speak for two (or more) named characters in the same scene ("RP both {Character} and {Character}", "let Elga and Sidunric talk", etc.), that NPC must format the reply exactly like this: CharacterOne: action/description in asterisks Spoken line or inner thought. CharacterTwo: action/description in asterisks Spoken line or inner thought. CharacterThree: action/description in asterisks Spoken line or inner thought. CharacterFour: action/description in asterisks Spoken line or inner thought. Alternate one block per speaker, never merging them. Keep each character's voice, personality, and physical quirks perfectly intact. Everything said in these replies are to be remembered by each respective character even though the context isn't in their JSON files. Continue the back-and-forth naturally until the conversation pauses or the player interrupts. If one character is silent for a beat, still give them a labeled block to show body language or reaction. Never narrate as the player or break the labeling system.
5. Gathering NPCs & Conversation:

Gather NPCs in the same place (ideal for meetings). When speaking to the main NPC (settlement owner/meeting organizer), end your statement with:

*RP all four characters in the same reply using Hecard:, Servic:, Richelda:, Servic: labels so we can follow their back-and-forth easily.*

⚠️ Important: Always name each NPC involved to maintain consistency.

6. Note on Usage:

Generating larger responses to complicated prompts can use more tokens from Player2. Report any bugs encountered while using the dual-conversation rule.

🔄 ChatSync Submod

🤝 Enhanced Multi-NPC Conversations with ChatSync

What is ChatSync?

ChatSync is a submod for AI Influence that synchronizes conversations between selected NPCs. Once synced, characters share the same conversation context, making them aware of what has already been said and eliminating the need to repeat dialogue. This creates a true multi-NPC conversation experience instead of isolated one-on-one interactions.

Download: ChatSync on Nexus Mods

Key Features:
  • Select multiple NPCs to sync conversations
  • AutoSync mode to keep dialogue context shared
  • NPC search for quick selection
  • Easy in-game UI with intuitive hotkeys
  • Ideal for companions, advisors, rulers, and role-play focused gameplay
  • Universal path detection for all installation types
How to Use ChatSync:

Hotkeys:

  • F8 – Open/close ChatSync menu
  • F9 – Toggle AutoSync ON/OFF instantly
  • F10 - Show Diagnostics
  • F11 - Manual Path Setup (if automatic detection fails)
Installation:
  1. Download ChatSync from Nexus Mods
  2. Place the ChatSync folder in your Bannerlord Modules folder
  3. Ensure it loads after AI Influence in your load order
  4. Launch game and use F8 to open the ChatSync menu
Smart Path Detection:

ChatSync automatically searches for AI Influence in ALL possible locations:

  • Steam Workshop installations (all drives and library folders)
  • Different mod managers (Vortex, ModOrganizer2, manual installs)
  • Custom installation paths on any drive (C:, D:, E:, etc.)
  • Standard Bannerlord directories
  • Windows user folders (Documents, AppData)
Troubleshooting:

If you encounter "NPC not found" issues:

  1. Press F10 to see diagnostics
  2. Check if AI Influence mod is found
  3. Press F11 to manually set the path if needed
  4. Enter the full path to your AI Influence save_data folder

✅ Tip: ChatSync greatly enhances immersion by allowing NPCs to have shared memory and context, making group conversations feel natural and dynamic!

⏪ Rollback AI Actions

🔄 Step-by-Step Rollback Guide

Scenario:

AI does something undesirable (e.g., Raganvad spamming war declarations on his own faction).

Step 1: Preparation

Have a save from before the problematic events. If not, proceed cautiously.

Step 2: Locate Mod Files

Navigate to mod installation folder (Nexus manual download recommended):

Steam Path: Drive:\PathToSteamInstall\workshop\content\261550\3584621421
Step 3: Find Character JSON

Use the JSON editing tutorial to find the specific character file.

Warning: Multiple results may appear if you have multiple campaigns.
Step 4: Edit JSON Sections

Look for these sections in the JSON file:

  • "ConversationHistory"
  • "LastDynamicResponse"
  • "LastAIResponseJson"
Step 5: Clean ConversationHistory

Delete problematic sections from ConversationHistory. Leave it formatted with their last reply.

Step 6: Update LastDynamicResponse

Copy the last line from ConversationHistory (without quotation marks or character name) and paste into "LastDynamicResponse" inside quotation marks.

Step 7: Update LastAIResponseJSON

Repeat for "LastAIResponseJSON" - paste in correct spot inside quotes.

Step 8: Save & Reload

Save the JSON file and reload your previous save game.

🗣️ How to Issue Political Decisions (War, Peace, Alliances) via Governor:

⚔️ NPC Action System & Rules

📋 NPC ACTION SYSTEM - REFERENCE GUIDE

What is the Action System

NPCs in AIInfluence can perform various actions: travel across the map, follow the player, attack enemies, besiege settlements, etc.

Multi-tasking actions: An NPC can perform multiple actions in sequence in one chain. For example, a player can ask an NPC to "visit city A, then city B, attack bandits and return" - and the NPC will complete all these tasks sequentially. Actions are combined with commas, creating a chain of tasks.

The actionrules.txt file allows you to add additional instructions for the AI that will be automatically added to the prompt in the "ADDITIONAL RULES FOR ACTIONS" section. This helps adjust AI behavior if it incorrectly uses actions or does something differently than you need.

All Available NPC Actions

2.1. Movement & Basic Actions

  • follow_player - NPC follows the player, accompanies them
  • go_to_settlement - NPC travels to the specified settlement (city, castle, village)
  • return_to_player - NPC returns to the player after completing a task
  • attack_party - NPC attacks the specified party (bandits, deserters, enemies)
  • patrol_settlement - NPC patrols around the specified settlement
  • wait_near_settlement - NPC waits near a settlement without entering it
  • siege_settlement - NPC besieges the specified city or castle
  • raid_village - NPC raids the specified enemy village
  • create_party - NPC creates their own party (leaves the player's party)

2.10. transfer_troops_and_prisoners

What it does: NPC transfers specific troops and/or prisoners between their party and the player's party.

When used: When the player asks the NPC to give or receive specific troops/prisoners, or when the NPC offers to transfer them.

Available: Only to NPCs with mobile parties (not in player's party).

Important: NPC must have the troops/prisoners in their party to transfer them. Use exact string_ids from "Your Forces" and "Your Captives" sections in the prompt.

2.11. Multi-tasking actions (chains)

What it does: NPC can perform multiple actions in sequence in one chain

Examples of chains:

- Visit multiple settlements: "go to city A, then to city B, then return" - Complete a task and return: "attack bandits and return to me" - Combined tasks: "visit a city, then patrol it, then return"

NPCs can combine actions with commas, creating a sequence of tasks that will be completed one after another.

Dialogue Actions (decision)
  • attack - NPC decides to attack the player
  • surrender - NPC surrenders to the player
  • accept_surrender - NPC accepts the player's surrender as a prisoner
  • release - NPC releases the player peacefully (does not attack)
  • propose_marriage - NPC proposes marriage to the player
  • accept_marriage - NPC accepts the player's marriage proposal
  • reject_marriage - NPC rejects a marriage proposal
  • intimate - Intimate interaction with NPCs
Financial Actions
  • money_transfer - Money transfer between NPC and player

Important: Used only when the NPC AGREES to transfer money, not for offers or refusals.

Workshop Actions
  • workshop_action (sell) - NPC sells their workshop to the player

Important: Used only after final price agreement, not during negotiations.

Roleplay Item Creation
  • create_rp_item - NPC creates a roleplay item (letter, document, note, sign, etc.) and automatically gives it to the player. The NPC must check the player's inventory first to avoid duplicates.
Diplomatic Actions (kingdom_action)

Available only to kingdom rulers and vassals in certain situations:

  • declare_war - Declaration of war on another kingdom
  • propose_peace / accept_peace / reject_peace - Peace proposal, acceptance or rejection
  • propose_alliance / accept_alliance / reject_alliance / break_alliance - Alliance operations
  • propose_trade_agreement / accept_trade_agreement / reject_trade_agreement / end_trade_agreement - Trade agreements
  • demand_territory / transfer_territory - Demand or transfer of territory
  • demand_tribute / accept_tribute / reject_tribute - Tribute operations
  • demand_reparations / accept_reparations / reject_reparations - Reparations operations
  • transfer_kingdom - Transfer kingdom leadership from one ruler to another. This is a permanent, major decision. Use only when explicitly agreed upon in dialogue. Recipient must be a vassal with sufficient prestige.
Recruitment Actions (kingdom_action)
  • hire_mercenary - Hiring the player as a mercenary
  • dismiss_mercenary - Dismissal of the player from mercenaries
  • offer_vassalage - Offer to the player to become a vassal
  • dismiss_vassal - Release of the player from vassalage
  • join_player_clan - NPC joins the player's clan as a companion
  • join_player_kingdom - NPC's clan joins the player's kingdom
  • hire_mercenary_clan - NPC's clan accepts the player's offer to hire them as mercenaries
  • kick_from_clan - NPC accepts the player's decision to dismiss them from the clan
  • dismiss_npc_mercenary - NPC's clan accepts the player's decision to dismiss them from mercenaries
  • release_npc_vassal - NPC's clan accepts the player's decision to release them from vassalage
How to Add Custom Rules to actionrules.txt

Creating the file:

  1. Find the AIInfluence mod folder (usually in Modules/AIInfluence/)
  2. Create a text file named actionrules.txt in the root of the mod folder
  3. Add your rules to this file (in English)

Rule format:

Rules are written in English in free form. They will be automatically added to the "ADDITIONAL RULES FOR ACTIONS" section of the AI prompt.

Rules should be written as instructions for the AI, explaining:

  • When to use or NOT use certain actions
  • What checks to perform before using actions
  • How to consider NPC personality when making decisions
  • Additional restrictions or conditions

Rule writing style:

  • Use imperative form ("NPC should...", "Always verify...", "Never use...")
  • Be specific and clear
  • Specify specific actions and conditions
  • Can reference NPC personality ("Consider personality when...")
  • Can add example situations
Good rule examples: - NPC should always verify settlement information is provided in the prompt before using go_to_settlement action. If settlement details are missing, NPC should say "I don't know which settlement you mean" and NOT use the action. - NPC with high honor trait should refuse to raid friendly or neutral villages, even if player orders it. They should explain their refusal based on their principles. - NPC should never attack settlements that belong to their own kingdom or allied kingdoms, even if player suggests it.
Bad rule examples (too general):
  • NPC should be careful
  • Don't do bad things
  • Think before acting
Examples of Rules for Different Situations

Rules for information verification:

- CRITICAL: Before using any action that requires settlement or party information (go_to_settlement, attack_party, patrol_settlement, siege_settlement, raid_village, wait_near_settlement), NPC MUST verify that the necessary information is provided in the prompt. If information is missing or unknown, NPC should stay in character, express uncertainty, and NOT use the action. - NPC should never guess or invent information. Only use actions when the necessary details are clearly available in the prompt.

Rules for considering NPC personality:

- NPC with high honor trait should refuse to raid villages unless they are clearly enemy villages. They should explain their refusal based on honor and principles. - NPC with cruel trait is more likely to agree to raid villages, but should still verify the target is an enemy. - NPC with calculating trait should consider the strategic value and risks before agreeing to siege_settlement or attack_party actions.

Rules for preventing errors:

- NPC should NEVER use attack_party, siege_settlement, or raid_village actions against targets that belong to their own kingdom, allied kingdoms, or friendly factions. Always check the faction relationship before using combat actions. - NPC should verify the target settlement's faction status before using siege_settlement. If the settlement belongs to an ally or neutral faction, NPC should refuse and explain why.

⚔️ Battle Combat Rules (battlecombatrules.txt)

🎖️ Formation Captain AI – How It Works

What is battlecombatrules.txt?

This file governs the behaviour of AI formation captains during real‑time battles. Each captain (Infantry, Ranged, Cavalry, HorseArcher) receives a tactical prompt every few seconds and must respond with a JSON object containing orders, shouts, and a tactical note. The system uses your configured AI backend (Player2, OpenRouter, etc.) to generate these responses.

Real triggers (when the AI is called)
  • Battle start – after deployment finishes, the first [CAPTAIN_REQUEST] is sent.
  • Periodic ticks – roughly every 5‑10 seconds ([TICK #N]).
  • Formation status change – when a formation becomes engaged, routing, or changes distance to enemy.
  • Player voice order – when you use [BATTLE_ORDER] (e.g., "Archers attack!"), the captain receives an updated context.
  • Significant casualties or terrain events – the prompt includes history and terrain features, so the AI can react to losses or obstacles.
💡 Captain memory: The captain does not remember previous decisions across ticks. Each prompt is self‑contained but includes a short battle history (e.g., "t6s: 197/197 idle"). This allows limited adaptation.
How to fill out battlecombatrules.txt

You do not need to edit the file manually for normal use – it is a fixed ruleset. However, if you want to customise captain behaviour, you can add rules at the end of the file (similar to actionrules.txt). The system adds these rules to every captain's prompt.

Example custom rule:

- When enemy holds high ground and my formation is infantry, always try to move to secure nearby high ground before charging. - If a cliff edge is within 50m ahead, never order a charge; instead use fall_back or move sideways. - Ranged formations should hold fire until enemy is within 150m, then fire at will.
JSON response format (what the captain outputs)
{ "response": "Battle shout – 1 sentence, short, in character", "orders": [ { "formation": "infantry", // your formation type (lowercase) "movement": "move", // charge, move, stand_ground, advance, fall_back, retreat, follow_me "move_direction": "flank_right", // forward/back/left/right/flank_left/flank_right (optional) "move_distance": 51, // integer meters (optional) "arrangement": "shield_wall" // line, shield_wall, loose, circle, square, skein, column, scatter } ], "troop_shouts": [ { "formation": "infantry", "phrase": "Shield wall!" }, { "formation": "infantry", "phrase": "To the high ground!" } ], "tactical_note": "Brief reasoning (optional but recommended)" }

Rules:

  • Only include fields that change. Omit unchanged or null fields.
  • formation must always be your own formation type (infantry, ranged, cavalry, horsearcher).
  • response is what the captain shouts – keep it brief and in‑character.
  • troop_shouts are soldier reactions (3‑8 short phrases).
  • tactical_note helps debugging and shows the AI's reasoning.
Real example from the log (Serala Aegarax, Infantry)

Situation:

  • Infantry 197/197, Line, Idle, 339m from enemy, 25m below enemy elevation.
  • High ground 51m to the right, cliff edge 73m ahead (danger), forest to the side.
  • Allied Ranged 15m behind, HorseArcher 55m left.

Captain's actual JSON response:

{ "response": "Infantry, advance in shield wall! Keep formation tight and take the high ground to our right!", "orders": [ { "formation": "infantry", "movement": "move", "move_direction": "flank_right", "move_distance": 51, "arrangement": "shield_wall" } ], "troop_shouts": [ { "formation": "infantry", "phrase": "Shield wall!" }, { "formation": "infantry", "phrase": "To the high ground!" }, { "formation": "infantry", "phrase": "We follow the commander!" }, { "formation": "infantry", "phrase": "Hold formation tight!" }, { "formation": "infantry", "phrase": "For the Ashwind!" }, { "formation": "infantry", "phrase": "Right flank, move!" } ], "tactical_note": "Enemy holds elevated position but severely outnumbered. Moving right 51m to secure high ground negates elevation advantage. Shield wall protects against their limited ranged units. Cliff ahead makes direct charge dangerous." }

What happened in game: The orders were executed, the captain's shout was heard, and soldiers responded with the troop shouts.

Tactical decision rules (built into the mod)
  • Terrain priority: High ground → move to secure it; forest → use as cover (good for ranged, bad for cavalry); cliff edge → never charge forward.
  • Formation identity: Infantry use shield_wall/line/advance; Ranged use fire_at_will/skein/loose (never charge); Cavalry use charge/flank_left/right; HorseArcher use skein/fire_at_will/keep distance.
  • Tactics skill level: Low (0‑100) → simple orders (charge, advance). High (200‑300) → complex flanking, terrain use, formation switches.
  • Morale: 80‑100 = aggressive; 50‑79 = cautious; below 50 = fall_back/retreat.
  • Elevation: Above enemy → charge/advance; below enemy → move to high ground or use ranged.
Common mistakes and how to avoid them
  • ❌ Issuing orders to the wrong formation – always set "formation" to your own type.
  • ❌ Omitting required fields – include at least response and orders (even empty).
  • ❌ Writing long, narrative shouts – keep shouts to one short sentence.
  • ❌ Forgetting to update the tactical note – helps debugging and shows intelligent behaviour.
  • ✅ Always check terrain features and elevation before deciding movement.
  • ✅ Use tactical_note to explain your reasoning (especially for complex manoeuvres).

✅ Tip: If you want to test your custom rules, enable detailed logging in MCM (Debug → Enable Battle AI Logging) and inspect logs/mod_log.txt to see what prompts and responses are being sent.

🔐 prompts/world_data/world_secrets.json

What: Secret knowledge that NPCs may know.

Format:

[ { "id": "unique_id", "description": "Description for the AI", "knowledgeChance": 50, "applicableNPCs": ["lords"], "accessLevel": "high", "tags": ["optional"] } ]

How it works:

  1. On the first interaction with an NPC (while KnowledgeGenerated: false), a 0–100 roll is made
  2. If ≤ knowledgeChance → the NPC learns the secret
  3. The secret is added to the prompt: "Secrets: ... (access: high)"
  4. The AI decides whether to reveal it (depends on trust)
  5. After generation, the flag KnowledgeGenerated: true is set — no further rolls
Important: Use knowledgeChance, NOT usageChance!

Fields:

  • id — unique name
  • description — full text (passed into the AI prompt)
  • knowledgeChance — 0–100 chance that the NPC learns it on first contact
  • applicableNPCs — types: all, lords, companions, faction_leaders, village_notables, merchants
  • accessLevel — low, medium, high (shown in the prompt)
  • tags — for organization (does not affect logic)

[ { "id": "unique_id", "description": "Description (you can use {character})", "usageChance": 75, "applicableNPCs": ["all"], "category": "world" } ]

  • applicableNPCs — types: all, lords, companions, faction_leaders, village_notables, merchants

Differences from secrets:

  • Field: usageChance vs knowledgeChance

🛠️ Common Tasks

Add a secret

  1. Open save_data/[CAMPAIGN_ID]/prompts/world_data/world_secrets.json
  2. Add an object to the array with knowledgeChance, not usageChance
  3. Save → hot‑reloaded automatically

Give a secret to a specific NPC

  1. Open the NPC file: save_data/[CAMPAIGN_ID]/Name (string_id).json
  2. Find "KnownSecrets" and add the secret ID
  3. Save. Ensure KnowledgeGenerated: true so the system doesn't re‑roll dice

Change an NPC's character

  1. Open the NPC file
  2. Edit "CharacterDescription": "Your character description"
  3. Save

Find the campaign ID

  1. Open logs/mod_log.txt
  2. Look for: Created save directory: ...\save_data\b7ed0c2f2399
  3. The last part is your campaign ID
  4. Or: MCM → Debug → Show Save Folder Info

Reset NPC data

  • MCM → NPC Management → Clear Current Campaign NPC Data (deletes all)
  • MCM → NPC Management → Erase Specific NPC (deletes one)
  • Manually delete the file save_data/[ID]/Name (string_id).json

Regenerate NPC knowledge (secrets/info by chance)

  1. Open the NPC file
  2. Set "KnowledgeGenerated": false
  3. Start a new dialogue — the system rolls again for entries not yet in the NPC's lists

⚙️ Important Rules

JSON files

  • ✅ Always validate JSON (jsonlint.com)
  • ✅ Make backups before editing
  • ✅ Do not delete required fields
  • ❌ Do not edit aiinfluence_campaign_diplomacy.json and other system files unless necessary

Secrets vs Info

  • world_secrets.json → field knowledgeChance
  • world_info.json → field usageChance
  • DO NOT CONFUSE THEM! Otherwise the value will be treated as 0.

Hot Reload

These files reload automatically (by modification time):

  • ✅ prompts/world_data/world.txt
  • ✅ prompts/world_data/world_secrets.json
  • ✅ prompts/world_data/world_info.json
  • ✅ prompts/world_data/cultural_traditions.json
  • ✅ prompts/rules/*.txt (on next access)

NPC files are reloaded on the next interaction.

KnowledgeGenerated Flag

  • false → on first dialogue the system rolls dice for secrets/info
  • true → automatic knowledge generation disabled; manual edits to KnownSecrets/KnownInfo are preserved
  • NPC reset via MCM creates a new context with KnowledgeGenerated: false

🔄 Workflow

Adding new content

  1. Come up with an idea (secret, event, quest)
  2. Add it to JSON (world_secrets.json or world_info.json in the campaign folder)
  3. Save the file → hot‑reload
  4. Create new NPCs or reset existing ones (or set KnowledgeGenerated: false)
  5. Start a dialogue → the AI will know about the new content

Testing secrets

  1. Add a secret with knowledgeChance: 100
  2. Create a new NPC or reset an existing one
  3. Start a dialogue
  4. Check the log: [NPC] Name learned secret: ...
  5. Ask the NPC about the secret directly

Debugging events

  1. Enable Enable Detailed Info Logging (MCM)
  2. Create an event (Force Generate Event Now in MCM)
  3. Check logs/dynamicEvents.log
  4. See who received the event and why
